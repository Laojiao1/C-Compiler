# 0. C++ 指针精讲

## Level 1：原生指针的物理本质与内存视角

### 1. 指针到底是什么？
在 64 位操作系统（比如你用的 x86_64 CPU 或现代 GPU）下，**指针就是一个 64 位的无符号整数（8 个字节大小）**。
不管这个指针是指向一个 1 字节的 `char`，还是指向一个占用几百 MB 的巨型 `Tensor` 结构体，**指针本身永远只占 8 个字节**。它里面存放的值，就是虚拟内存空间中的一个地址编号。

```cpp
int a = 42;       // 在 Stack（栈）上分配 4 个字节，存入 42
int* p = &a;      // 在 Stack 上再分配 8 个字节存指针 p，里面保存了 a 的首地址
*p = 100;         // 通过地址找到那 4 个字节，修改内容为 100
```

**汇编层面：**

在 CPU 看来，根本没有“指针”这个概念。当你执行 `*p = 100` 时，编译器生成的汇编指令大概是这样的：

`mov DWORD PTR [rbx], 100`  （假设指针的值存在 `rbx` 寄存器里，`[rbx]` 就代表去读取/写入这个地址指向的内存）。

**解引用 (`*p`) 的本质，就是一次 CPU 的访存操作（Load/Store）。** 在高性能计算中，最怕的就是指针乱指（Cache Miss），导致 CPU 苦等内存数据。

### 2. 既然都是 8 字节，为什么还要分 `int*`、`float*` 和 `void*`？
这是很多新手疑惑的地方：既然指针只是个地址，为什么要有类型？其实类型只服务于两件事：**“解读步长”** 和 **“内存运算”**。

**① 解读步长（内存怎么切分）**

内存是一片连续的字节数组（每个格子 1 字节）。当你拿到一个地址 `0x1000` 时：

- 如果它是 `char*`，解引用时 CPU 只读 1 个字节。
- 如果它是 `float*`，解引用时 CPU 会读 4 个字节，并按 IEEE 754 浮点数格式解码。
- 如果它是 `void*`，它纯粹只是个地址，**无法解引用**，因为编译器不知道该读几个字节。（在手写底层内存池时，我们经常先分配一大块 `void*` 内存，再通过类型转换 `reinterpret_cast` 把它当成特定对象来用）。

**② 指针算术（Pointer Arithmetic）—— 算子开发的核心**

如果你对指针加一，它在内存中前进的距离取决于**它指向类型的大小**。

```cpp
float* ptr = (float*)0x1000;
ptr = ptr + 1;  // ptr 变成了 0x1004 (因为 sizeof(float) 是 4)
```

**PyTorch/Triton 中的内存对齐与访存：**

在写深度学习算子（比如自己实现一个矩阵乘法或 Softmax）时，如果你有一个一维大数组来模拟二维 Tensor，你会大量依赖这种指针算术：

```cpp
// 假设矩阵维度是 [Row, Col]，我们在计算 [i, j] 的内存地址：
float* data = tensor.data_ptr;
float* current_element = data + (i * Col + j); 
```
如果类型不对，你的内存指针就会完全偏移，读出“乱码”数据（往往表现为 Loss 变成 NaN）。

### 3. 悬垂指针 (Dangling Pointer) 与野指针 (Wild Pointer)
在造轮子时，这是导致 Segfault（段错误）的罪魁祸首。
- **野指针**：只声明了指针，但没有初始化（`int* p;`），它里面存着随机的垃圾地址。解引用直接崩溃。
- **悬垂指针**：指针指向的内存**已经被释放了**，但指针还在。
  ```cpp
  int* create_tensor_data() {
      int data[100]; // 栈上分配
      return data;   // 致命错误：函数结束后 data 就被销毁了！
  }
  int* p = create_tensor_data();
  // 此时 p 指向了一段已经归还给操作系统的内存（悬垂指针），后续访问 p 就是未定义行为 (UB)。
  ```

在 C++ 中，为了从根本上消灭这种悬垂指针，现代 C++ 才引入了 **RAII（资源获取即初始化）和智能指针**（这是我们后续要重点攻克的阶段）。

## Level 2：指针常量和常量指针

### 1. 指针与数组的语法羁绊
在 C++ 语法中，数组名在很多情况下会**退化（Decay）成一个指向它首元素的指针**。
```cpp
int arr[5] = {10, 20, 30, 40, 50};
int* p = arr;  // 语法允许：arr 自动退化为 &arr[0]

// 下面这三种写法，在语法上是完全等价的：
int a = arr[2];    // 数组下标语法，取到 30
int b = *(p + 2);  // 指针算术语法，取到 30
int c = p[2];      // 指针当数组用的语法，取到 30
```
**注意语法上的区别**：`sizeof(arr)` 是整个数组的大小（20字节），而 `sizeof(p)` 永远是 8 字节（64位系统下的指针大小）。

### 2.  `const` 与 指针
在 C++ 里，`const` 关键字和 `*` 的相对位置决定了到底是**地址不能变**，还是**地址里面的内容不能变**。

绝招：**“从右向左读”（或者看 `const` 修饰的是谁）**。

*   **语法 1：指向常量的指针 (Pointer to const)**
    ```cpp
    int x = 10;
    const int* p = &x;  // 或者 int const * p = &x; (等价)
    // 语法约束：你不能通过 p 去修改 x 的值。
    // *p = 20;  // ❌ 语法错误！编译器不让改
    p = nullptr; // ✅ 语法正确。p 的指向可以变。
    ```
*   **语法 2：常量指针 (Const pointer)**
    ```cpp
    int y = 10;
    int z = 20;
    int* const p = &y;  
    // 语法约束：p 里面存的地址焊死了，不能再指向别人。
    // p = &z;   // ❌ 语法错误！p 的地址不能变
    *p = 100;    // ✅ 语法正确。可以通过 p 修改 y 的值。
    ```
*   **语法 3：终极叠加 (指向常量的常量指针)**
    ```cpp
    const int* const p = &x; 
    // 地址不能变，里面的值也不能通过 p 改变。
    ```

### 3. 函数传参语法：值传递 vs 指针传递
这是最基础也是最常用的语法。C++ 默认是“值传递”（Copy），如果要在函数里面修改外面的变量，就必须传指针。

```cpp
// 语法 A：值传递（传进来的只是个拷贝，原变量不受影响）
void addOne_Value(int x) {
    x = x + 1;
}

// 语法 B：指针传递（把变量的地址传进来，通过地址直接改老窝）
void addOne_Pointer(int* p) {
    if (p != nullptr) { // 基础防御语法：永远记得判空
        *p = *p + 1;
    }
}

int main() {
    int num = 5;
    addOne_Value(num);     // num 还是 5
    addOne_Pointer(&num);  // 传入 num 的地址，num 变成了 6
    return 0;
}
```

### 总结

1. **`int* const p`**：
   - **读法**：从右向左读，`p` 是一个 `const` (常量)，它是一个 `*` (指针)，指向 `int`。
   - **本质**：**指针本身是常量**。
   - **行为**：`p` 里面存的地址不能变（不能再指别人），但可以通过 `*p` 去改那个地址里的值。

2. **`const int* p` (或 `int const* p`)**：
   - **读法**：从右向左读，`p` 是一个 `*` (指针)，指向一个 `int` 类型的 `const` (常量)。
   - **本质**：**指向常量的指针**。
   - **行为**：`p` 里面存的地址可以变（可以换个地方指），但绝对不能通过 `*p` 去修改那个地址里的值。

在很多国内的 C++ 教材、面试题甚至博客中，大家对 **“常量指针”** 和 **“指针常量”** 这两个词的叫法极其混乱，经常互相叫反，**因此强烈建议彻底抛弃“常量指针”和“指针常量”这两个缩写词**。

以后在心里直接叫它们的全称：
- **“指针本身是常量”** ：`int* const p`
- **“指向常量的指针”** ：`const int* p`

结合这两个全程和“从右向左看”的拆解法，这块语法就永远不可能再把你绕进去了

## Level 3：new 和 delete 语法与内存泄露

### 1. 栈 (Stack) vs 堆 (Heap)

在聊语法前，必须先建立直觉：
*   **栈 (Stack)**：你可以把它想象成“快餐店的流水线”。
    *   **特点**：极快、空间小（通常每个线程只有几 MB）、**自动管理**。
    *   **语法表现**：你平时写的 `int x = 10;` 或者 `float arr[100];` 全在栈上。函数一结束，这块内存立刻被系统自动收回。
*   **堆 (Heap)**：你可以把它想象成“巨大的公共仓库”。
    *   **特点**：极大（可以用尽系统的几十 GB 内存）、稍微慢点、**全手动管理**。
    *   **语法表现**：当你在运行期间，突然发现你需要一个巨大的 Tensor（比如 100MB），栈根本放不下，或者这个 Tensor 必须在函数结束后还要继续存活，你就必须去**堆**里借空间。

### 2. `new` 和 `delete` 的基本语法

在 C++ 中，向堆（操作系统）借内存的语法是 `new`，还回去的语法是 `delete`。

#### 语法 A：单个对象的借与还
```cpp
// 1. 借内存：在堆上申请 4 个字节存 int，初始值为 42
// new 会返回这块内存的地址，我们必须用指针 p 接住它
int* p = new int(42); 

// 此时 p 本身（8字节）活在栈上，但它里面存的地址指向广阔的堆。

*p = 100; // 使用这块内存

// 2. 还内存：用完了，必须显式告诉系统“我还给你了”
delete p;

// 3. 防御性编程：还完内存后，p 里还存着原来的地址（悬垂指针），为了安全立刻把它清空！
p = nullptr; 
```

#### 语法 B：数组（批量）的借与还
在算子开发中，我们绝大部分时间是在搞数组。
```cpp
// 1. 借：在堆上连续申请 1000 个 float 的空间（相当于申请了一块 Tensor 显存/内存）
float* data = new float[1000];

data[0] = 1.0f; // 像普通数组一样用

// 2. 还：【⚠️ 致命易错点】如果是借了数组，还的时候必须加 []
delete[] data; 
data = nullptr;
```
**提醒**：如果你写了 `delete data;` 而不是 `delete[] data;`，对于基本类型（如 float）可能只是轻微的内存泄漏；但如果数组里是复杂的对象（比如一千个 `std::thread` 对象），编译器就**只会调用第一个对象的析构函数**，剩下的 999 个直接成了“孤魂野鬼”，导致极其严重的资源泄漏！

### 3. 内存泄漏（Memory Leak）是怎么发生的？

在 C/C++ 里，操作系统对“堆”的态度是：**你不主动 `delete`，我就永远不收回，哪怕你的指针变量已经死了。**

看看下面这个经典的惨剧：

```cpp
void createTensor() {
    float* ptr = new float[1000000]; // 借了 4MB 内存
    
    // ... 做了些计算 ...
    
    // 函数结束了，糟糕！我忘了写 delete[] ptr;
} 

int main() {
    while(true) {
        createTensor(); // 每次循环，吞掉 4MB 堆内存
    }
}
```
**发生了什么？**

当 `createTensor` 函数结束时，活在**栈**上的指针变量 `ptr` 被自动销毁了。但是！它指向的那 4MB **堆**内存并没有被归还。

这就好比：**你租了一个仓库，把唯一的钥匙（指针）给丢了，这仓库你进不去，房东（OS）也以为你还在用，不敢租给别人。**

这就是内存泄漏。程序跑得久了，内存会被吃光，然后被系统无情地 Kill 掉（OOM）。

### 4. 为什么要引入这些
你会发现，每次调用 `new` 和 `delete`，底层其实都要和操作系统打交道（去遍历哪里有空闲内存）。这是一个**非常慢**的过程。

所以在高性能计算、手写 Thread Pool 或者 LRU Cache 时，我们绝对不会在运算的核心循环里去 `new` 和 `delete`。

我们通常的做法是：**在一开始 `new` 出一整块巨大的内存（这就是 Memory Pool 的雏形），然后自己写逻辑用指针在这块大内存里切分、重用。**

## Level 4：RAII 与智能指针的雏形

### 1. 核心机制：析构函数语法与 RAII
在 Level 3 里我们说过，**活在栈（Stack）上的变量，在函数结束时会被系统自动回收**。

C++ 语言的创造者利用了这一点，发明了一个极其聪明的语法机制：**析构函数 (Destructor)**。

```cpp
class MyBox {
public:
    int* ptr;

    // 构造函数：诞生时调用
    MyBox() { 
        ptr = new int[1000]; // 偷偷去堆里借内存
    }

    // 析构函数（名字前加个波浪号 ~）：死亡时自动调用！
    ~MyBox() { 
        delete[] ptr;        // 临死前，自动把堆内存还回去
    }
};

void test() {
    MyBox box; // box 这个对象活在栈上
    // ... 做一些计算 ...
} // ⚠️ 重点：函数结束，栈上的 box 被销毁，触发它的析构函数 ~MyBox()，堆内存被自动释放！
```
这就是 C++ 中最伟大的发明之一，叫 **RAII（资源获取即初始化）**。

**它的语法本质是**：把需要手动 `delete` 的堆内存，包装进一个栈上的对象里。利用栈对象生命周期结束时自动调用析构函数的语法特性，来替我们执行 `delete`。

现代 C++（C++11 开始）的标准库已经为你提供好了现成的“Box”，就是我们常说的**智能指针**。你以后写代码，基本不再需要手动写 `new` 和 `delete` 了。

### 2. `std::unique_ptr` (独占式指针) 的基础语法

这是你以后写代码最常用、性能最好（零额外开销）的指针。它表示**“这段堆内存，只有我一个人拥有”**。

```cpp
#include <memory> // 必须包含这个头文件

void test_unique() {
    // 语法：用 std::make_unique 在堆上申请内存，并交给 unique_ptr 管理
    std::unique_ptr<int> p1 = std::make_unique<int>(42);

    // 像原生指针一样使用（解引用）
    *p1 = 100;

    // ❌ 语法报错：独占式指针，严禁拷贝！因为如果你拷贝了，就变成两个人拥有它了。
    // std::unique_ptr<int> p2 = p1; // 编译直接报错！

    // ✅ 语法正确：如果你非要给别人，只能用 std::move "转移所有权"
    std::unique_ptr<int> p3 = std::move(p1);
    // 此时 p1 变成了空指针，内存的控制权完全交给了 p3

} // 函数结束，p3 死亡，自动调用内部的 delete，安全！
```

### 3. `std::shared_ptr` (共享式指针) 的基础语法

在写多线程（比如把一个大矩阵传给好几个线程并行计算）时，这段内存是共享的，不能被某一个线程独占。这时候就用 `shared_ptr`。

```cpp
#include <memory>

void test_shared() {
    // 语法：用 std::make_shared 在堆上申请内存
    std::shared_ptr<int> p1 = std::make_shared<int>(42);

    // ✅ 语法正确：共享指针，允许随意拷贝！
    std::shared_ptr<int> p2 = p1; 
    std::shared_ptr<int> p3 = p1;

    // 此时底层发生的事情：C++ 内部维护了一个“引用计数”。
    // p1, p2, p3 诞生时，计数变成了 3。
} 
// 函数结束时，p3 死了，计数变 2；p2 死了，计数变 1；
// 当 p1 也死了，计数变成 0，C++ 才会真正执行 delete！
```

## 一些琐碎的知识点

### 补充 1：引用 (`&`) 的底层其实就是指针
在 C++ 里，我们在函数传参时，经常纠结到底是传指针 `void func(int* p)` 还是传引用 `void func(int& r)`。
**语法真相**：在编译器（汇编）眼里，**引用就是指针**。
`int& r = x;` 在底层完全等价于上一关我们讲的常量指针 `int* const r = &x;`。

**语法的区别在于：**
1. **引用绝对安全**：指针可以为空 (`p = nullptr`)，但引用在声明时**必须初始化**，且永远不能为空。
2. **语法糖更甜**：使用引用时，不需要写繁琐的解引用符号 `*p` 和取地址符号 `&`，直接像用普通变量一样用 `r = 100;` 即可。

**开发建议**：在 C++ 中，**能用引用传参的地方，绝对不用指针**（除非这个参数有可能传个空值进来表示特殊含义）。

### 补充 2：类里面幽灵般的 `this` 指针
当你在手写数据结构（比如 LRU Cache 的 Node 节点）时，你一定会写类（Class）。

```cpp
class Node {
public:
    int value;
    void setValue(int value) {
        // ⚠️ 这里的 value 到底是类的成员变量，还是传进来的参数？
        // value = value; // 这样写会产生歧义，自己赋值给自己
        
        // 正确语法：使用隐藏的 this 指针
        this->value = value; 
    }
};
```
只要你在类的**非静态成员函数**里，编译器就会悄悄塞给你一个隐式指针，名字就叫 `this`。它的类型是 `Node* const this`（当前对象的常量指针），专门用来解决成员变量和参数重名的问题。

### 补充 3：最难写的语法——函数指针 (Function Pointer)
既然指针能指向一个数据（变量），那**指针能不能指向一段代码（函数）**？

- 当然可以！这在写**Thread Pool（线程池分发任务）**或者**调用 CUDA 底层 API 的回调函数**时是必杀技。

**原始 C/C++ 函数指针语法非常反人类**，它的 `*` 和括号是交织在一起的：

```cpp
// 一个普通的函数
void sayHello(int id) { /* ... */ }

// 语法：声明一个指向该函数的指针
// 格式：返回值类型 (*指针名字)(参数类型)
void (*funcPtr)(int) = &sayHello; 

// 通过指针调用函数
funcPtr(42); 
```

**现代 C++ 的写法：**

正是因为上面那种原生语法太难写了，现代 C++ 提供了 `<functional>` 库，你可以用 `std::function` 这种非常优雅的语法来代替原始的函数指针（这也是你以后写线程池任务队列时一定会用到的）：

```cpp
#include <functional>
// 语法变得像人类语言了：它是一个能装下 "参数为 int, 返回值为 void" 的函数的容器
std::function<void(int)> myTask = sayHello; 
```

## 常见的笔试题

### 第一题（初级）：经典 Swap 交换操作

**考点：** 深刻理解传值、传指针、传引用的区别。

```cpp
#include <iostream>

// 【写法 1】传指针：经典 C 语言写法
void swap_ptr(int* a, int* b) {
    int temp = *a; // 解引用 a，拿到原值
    *a = *b;       // 解引用 b 的值，赋给 a 所指的内存
    *b = temp;
}

// 【写法 2】传引用：现代 C++ 推荐写法
void swap_ref(int& a, int& b) {
    int temp = a;  // 没有繁琐的 *，直接操作引用
    a = b;
    b = temp;
}

int main() {
    int x = 10, y = 20;
    
    // 调用传指针版本：必须用 & 取变量的地址传进去
    swap_ptr(&x, &y); 
    
    // 调用传引用版本：没有任何特殊符号，语法极其干净
    swap_ref(x, y);   
    return 0;
}
```
**PS**：面试官如果问你更推荐哪种，一定要回答**推荐传引用 (`&`)**。因为在 `swap_ptr` 中，如果传入的是 `nullptr`，`*a` 会立刻引发段错误崩溃；而引用在语法层面上保证了绝对不为空，免去了防御性判空的开销。

### 第二题（中级）：优先级陷阱 

**考点：** 当 `*` 遇上自增符 `++` 时，编译器到底先算哪一步？

```cpp
int main() {
    int arr[] = {10, 20, 30};
    int* p = arr; // p 指向 10 (即 arr[0])

    // 【陷阱 1】 *p++ 
    int a = *p++; 
    // 逻辑：后缀 ++ 优先级极高，但它返回的是修改前的旧地址。
    // 结果：a 拿到了 10。然后 p 向后移动了 4 字节，指向了 20。
    
    // 【陷阱 2】 (*p)++
    // 此时 p 指向 20。
    int b = (*p)++;
    // 逻辑：括号强制先解引用拿到数值 20。然后对数值 20 进行后缀自增。
    // 结果：b 拿到了 20，但 arr 里的第二个元素变成了 21！p 依然留在原地。

    // 【陷阱 3】 *++p
    // 此时 p 依然指向第二个元素（数值已被改为21）。
    int c = *++p;
    // 逻辑：前缀 ++ 先让 p 向前移动 4 字节，指向 30。然后再解引用。
    // 结果：c 拿到了 30。
    
    return 0;
}
```
**秘诀**：看清楚 `++` 到底是作用在**地址**上，还是作用在**解引用后的数值**上。

### 第三题（高级）：在函数中分配内存

**考点：** 二级指针 (`**`) 与 指针的引用 (`*&`)。

**场景**：你想写一个函数，在函数内部向系统借一块堆内存，然后让外面的指针指向这块内存。

#### 错误写法（内存泄漏 + 悬垂指针）：
```cpp
void allocate_wrong(int* p) { 
    // 传进来的是外部指针的一个拷贝！
    p = new int(100); 
} // 函数结束，这个拷贝 p 死了，刚申请的 100 内存泄漏了！外部的指针丝毫未变。
```

#### 正确写法 1：C 语言的极限——二级指针 (`**`)
想要改变一个 `int`，得传 `int*`

同理，**想要改变一个 `int*`（即改变指针本身的指向），就得传 `int**`（指向指针的指针）！**

```cpp
void allocate_c_style(int** p) {
    // 解引用一次二级指针，拿到了外面的那根一级指针，给它强行塞入新地址
    *p = new int(100); 
}

int main() {
    int* myPtr = nullptr;
    allocate_c_style(&myPtr); // 必须对一级指针再取一次地址
    return 0;
}
```

#### 正确写法 2：C++ 的终极优雅——指针的引用 (`*&`)
在 LeetCode 刷链表题，或者大厂面试写底层的 C++ 代码时，这是标准答案：
```cpp
// 语法解析从右向左读：p 是一个引用(&)，它引用的是一个指针(*)，指向 int。
void allocate_cpp_style(int*& p) {
    // p 直接就是外部那个指针的真身！没有任何额外语法，直接赋值！
    p = new int(100); 
}

int main() {
    int* myPtr = nullptr;
    // 没有任何奇怪的符号，直接传进去，外部指针就被完美修改了
    allocate_cpp_style(myPtr); 
    return 0;
}
```
**PS**：在 C++ 的实际底层工程中，遇到需要修改外部指针指向的情况，**永远优先使用指针的引用 (`*&`)**，它完美避开了二级指针那令人眼花缭乱的 `**` 和 `&`，语法极其干净，且汇编效率极高。

# 总结

到这里，C++ 指针的基础语法体系就完整了：
1. **原生指针 (`*`)**：知道它是装地址的 8 字节整数，注意 `const` 的位置。
2. **堆内存 (`new`/`delete`)**：懂得了手动向系统借内存和还内存的语法（特别注意数组的 `delete[]`）。
3. **现代指针 (`make_unique`/`make_shared`)**：利用析构函数（RAII 机制），让编译器替我们自动执行 `delete`。

以后如果要写 AI 算子和架构代码，**原生的 `new`/`delete` 尽量不要碰了，但原生指针 `int*` 还是会大量用到**（比如 `unique_ptr::get()` 可以把底层原生指针取出来传给 C 语言写的底层 CUDA 接口）
